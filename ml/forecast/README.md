# DS‑1: прогноз и конкурсный CSV

Задача: [Issue #2](https://github.com/Dianka678/mthack-tram/issues/2).
Код использует агрегированные метки организаторов; обработка сырых транзакций
и подтверждение флагов качества остаются в зоне DS‑2. Результат — число
успешных валидаций/час, не заполненность вагона и не уникальные пассажиры.

## Обучение на Kaggle

Готовый автономный ноутбук: [DS1_Kaggle_Train.ipynb](DS1_Kaggle_Train.ipynb).
Импортировать в Kaggle, включить Internet, выбрать CPU и выполнить Run All.
По умолчанию `DATA_SOURCE='yandex'`: ноутбук автоматически скачивает архив
по https://disk.yandex.ru/d/DiFwlfMOauxjBg через официальный публичный API,
без токена. Скачивание потоковое во временную папку `/tmp`, с прогрессом,
повторами, докачкой при поддержке Range и проверкой размера/хеша/структуры ZIP.
Проверенный архив повторно не скачивается. Извлекаются только небольшие метки,
шаблон и описание; сырые CSV не распаковываются.

Ручной режим `DATA_SOURCE='input'` сохранён для приватных файлов через Add Input.
Доступ к GitHub не нужен; код моделей уже встроен. Используются библиотеки Kaggle,
их версии записываются в отчёт. Нужен Python 3.11+.

В `/kaggle/working/` будут `submission.csv`, `report.json`, `forecast_api.csv`;
модель находится в `ds1_results/`. Ноутбук и данные оставлять приватными.
При сетевых ограничениях/лимите Яндекс Диска ячейка останавливается с объяснением.
Встроенный код обновляется командой `python3 ml/forecast/build_notebook.py`.

## Входы и запуск

Python 3.12. Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/pip install -r ml/forecast/requirements.txt
```

Получить `dataset.zip` по [ссылке организаторов](https://disk.yandex.ru/d/DiFwlfMOauxjBg).
Для обучения достаточно двух небольших файлов меток и шаблона; извлекать
сырые 7,59 ГБ не требуется. Локально сохранённый ZIP можно разобрать так:

```bash
.venv/bin/python -m ml.forecast.prepare_inputs \
  --archive /absolute/path/dataset.zip --out data/organizer
```

Команда извлекает только `labels_day_train.csv`, `labels_day_test.csv`,
`test_submission.csv` и `README.md`, если он есть. Перед обучением прочитать
описание организаторов. Исходные файлы сохраняются неизменными, их SHA256
попадают в манифест. Повторное извлечение поверх существующих файлов запрещено.

Одна команда запускает временную проверку, выбор модели, переобучение на
январе–октябре и прогноз всех 61 дней целиком:

```bash
.venv/bin/python -m ml.forecast.run \
  --train data/organizer/labels_day_train.csv \
  --test data/organizer/labels_day_test.csv \
  --sample data/organizer/test_submission.csv \
  --out artifacts/ds1
```

`--profiles-only` явно отключает бустинг и позволяет выполнить пайплайн
стандартным Python без сторонних библиотек. Это другой набор кандидатов,
он отражается в отчёте. Случайная ошибка импорта не скрывается пропуском модели.
Обучение локальное; по умолчанию используются не более двух потоков OpenMP.

## Модели и проверка времени

- Контроли `mean_zero`, `median_zero`: маршрут × день недели × час, 20%
  сглаживания к маршрут × час. Метод и округление совпадают с
  `backtest_baseline.py` DS‑2 в PR #1.
- `mean_observed`, `median_observed`: те же профили, но без добавления
  отсутствующих строк в обучение. Это проверка чувствительности к пропускам;
  не восстановление сбоев и не доказательство истинного спроса.
- `mean_56d`: зарегистрированный кандидат по последним 56 дням.
- `hgb_direct`: HistGradientBoosting с абсолютной ошибкой, категориальными
  маршрутом, часом и календарём, порядковым днём и годовой гармоникой.
  Будущий целевой ряд не нужен ни на одном из 61 дней.
- `hgb_recursive`: тот же класс модели с лагами 24 и 168 часов и признаками
  доступности лага. Каждый будущий день дописывается **только предсказаниями**.
  При запросе поздней даты сначала рассчитываются все промежуточные дни.

Все параметры зафиксированы в `models.py` и выводятся в `report.json`.
Внешние погода, новости, расписание и официальный праздничный календарь
пока не включены: для них нужен согласованный модуль DS‑2 и отдельная абляция.
Обычный день недели не учитывает перенос рабочих дней; это ограничение
для 1–4 ноября и конца декабря. Здесь нет заявленного эффекта внешнего источника.

Май–июнь при обучении до 30 апреля и июль–август при обучении до 30 июня
используются для выбора кандидата по **суммарной абсолютной ошибке** двух
окон. Затем только этот кандидат и два заранее заданных контроля оцениваются
на сентябре–октябре с отсечением 31 августа. Кандидат остаётся, только если
лучше обоих контролей; иначе выбирается лучший baseline этого среза.
Сентябрь–октябрь участвует в выборе, поэтому его результат нельзя называть
независимой финальной оценкой обобщения. Неизвестный ноябрь–декабрь не участвует.

Глобальный score: `max(0, 1 - sum(abs(y-p))/sum(y))`. Проверка включает
каждый час каждого известного в истории маршрута. Пропущенные метки приняты
за нуль для счёта, отдельно выводятся число таких часов и их ошибка.
При `sum(y)==0` общий расчёт завершается ошибкой; у пустого отдельного среза
score равен `null`. Отчёт содержит маршруты, месяцы, часы 06–22/23–05 и четыре
пиковых часа каждого маршрута, определённые **только по его обучающей истории**.
Названия дневных/ночных часов — диагностические группы, не проверенное расписание.

## Результаты и контракты

В `artifacts/ds1/` создаются:

| Файл | Содержание |
|---|---|
| `submission.csv` | `route;date;hour;prediction`, точные строки и порядок исходного sample |
| `forecast_api.csv` | `route_id,timestamp_msk,pred_validations,model_version,source_mode` |
| `report.json` | Все метрики, выбранная модель, параметры, версии, SHA256 входов/кода/выходов, ограничения |
| `model.local.pkl` | Локальный обученный артефакт; не публиковать и не загружать pickle из недоверенного источника |

Время API — ISO 8601 `Europe/Moscow`, явный `+03:00`; метка задаёт начало часа,
интервал `[timestamp, timestamp + 1 hour)`. Прогнозы целые неотрицательные,
округление half-to-even; NaN/inf отвергаются, отрицательные оценки обрезаются
до нуля. Дневные/месячные значения потребитель получает суммой **этих же часов**.
Экспорт реализует существующий черновик контракта; согласование и импорт
со стороны fullstack ещё нужны. `source_mode=as_of_2025_10_31`.

Шаблон должен содержать 14 640 уникальных строк: десять маршрутов,
01.11–31.12.2025 и 24 часа, включая маршрут 5. Меняется только `prediction`;
текст остальных ячеек и порядок сохраняются. Оригинал sample не перезаписывается.
Если маршрут отсутствует во всей истории, используется **явный нулевой cold start**.
Для маршрута 5 это рабочее допущение, не измеренная точность: проверить стратегию
можно только при появлении достоверной истории или результата платформы.

Повторная независимая проверка готового CSV:

```bash
.venv/bin/python -m ml.submit.adapter \
  --sample data/organizer/test_submission.csv \
  --submission artifacts/ds1/submission.csv
```

`data/`, `artifacts/`, исходные ZIP и обученные модели не включать в PR.
В репозитории публикуются только код, тесты с искусственными примерами и
агрегированные результаты реально выполненных опытов. Загрузка на платформу
и человеческое принятие модели — отдельный шаг по `docs/PLAN.md`.

## Проверки

```bash
.venv/bin/python -m unittest ml.forecast.test_pipeline -v
```

Тесты проверяют строгую сетку, дубликаты, порядок sample, сохранность оригинала,
NaN/inf, округление, маршрут 5, равенство сумм CSV/API/день/месяц, полноту WAPE,
даты отсечения, запрет будущих меток, выбор на ранних окнах и рекурсивные лаги.
Искусственные тесты подтверждают работу кода, **не** качество на конкурсных данных.

Текущий протокол исполнения и ограничения: [VALIDATION.md](VALIDATION.md).

Полный прогон на воспроизводимых искусственных данных (включая бустинг):

```bash
.venv/bin/python -m ml.forecast.smoke --out artifacts/synthetic_check
```

Папка должна быть новой. В ней появится `SYNTHETIC_NOT_FOR_SUBMISSION.txt`,
а в версии модели и отчёте будет явная отметка об искусственных данных.
Этот CSV нельзя подавать в соревнование. Для проверки без библиотек добавить
`--profiles-only`.

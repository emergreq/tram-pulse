# Tram Pulse — прогноз спроса на трамвайных маршрутах

Tram Pulse помогает диспетчеру увидеть ожидаемую динамику спроса, сравнить обычный день со сценарием аварии, ремонта или дождя и оценить возможное перераспределение нагрузки. Основная прогнозируемая величина — число валидаций оплаты проезда по маршруту и часу.

## Что умеет сервис

- Показывает прогноз по часам на день и по дням на неделю/месяц; годовой горизонт доступен как отдельный сценарий.
- Позволяет выбрать маршрут, остановку/участок и часы, посмотреть данные на карте и выгрузить CSV/PDF.
- Сравнивает базовый прогноз с авариями, дорожными работами, дождём и предположениями о новой застройке.
- Предлагает условный план перераспределения спроса и использования резерва для проверки диспетчером.

## Производительность — реальные замеры HTTPS

Тест выполнен 27.09.2026 на работающем сайте. Приложение находится в **одном контейнере: 2 vCPU / 2 ГиБ RAM**. HTTPS-прокси и генератор нагрузки работают отдельно на той же ВМ; их CPU не входит в показатели контейнера. Сертификат проверен стандартным способом, без отключения проверки доверия. Продолжительность мониторинга — около 14.5 минуты, включая отдельный 10-минутный тест устойчивости.

| Проверка | Успешных запросов/с | p95, мс | Ошибки HTTP |
|---|---:|---:|---:|
| Почасовые прогнозы | 268.16 | 42.19 | 0 |
| Обычная работа, 8 клиентов | 123.81 | 116.84 | 0 |
| Обычная работа, 24 клиента | 126.39 | 268.24 | 0 |
| Недельные прогнозы | 259.13 | 43.01 | 0 |
| Загрузка CSV и чтение | 114.49 | 67.92 | 0 |
| Неделя с аварией и работами | 5.42 | 1028.05 | 0 |
| Формирование PDF | 8.19 | 131.07 | 0 |
| Обычная работа в течение 10 минут | 121.78 | 117.48 | 0 |

**Как читать результаты.** p95 — время, за которое завершаются 95% запросов. Выдача почасовых и недельных прогнозов достигает сотен запросов в секунду с p95 около 42–43 мс. Смешанная работа при 24 клиентах даёт 126 запросов/с и p95 268 мс; тяжёлый недельный сценарий — 5.42 запроса/с и p95 1028 мс. Поэтому единое обещание «сотни RPS при p95 <300 мс для всех операций» не заявляется.

При попытке подавать смешанную нагрузку 200 и 300 запросов/с выполнено соответственно 3780 из 6000 и 3805 из 9000 запланированных запросов. Ограниченная очередь генератора не приняла 2220 и 5195 запросов. Среди отправленных запросов ошибок HTTP не было, но p95 с учётом ожидания составил 593 и 587 мс. Эти режимы не подтвердили требуемую пропускную способность. Всего в нагрузочных этапах выполнено 107755 запросов без HTTP-ошибок; 7415 запланированных запросов не были отправлены. Пропуски не скрываются за формулировкой «0 ошибок».

За 10 минут обычной работы: **121.78 запроса/с, p95 117.48 мс; память 134.17–135.39 МиБ; swap 0; событий нехватки памяти нет**. CPU — 50.04% выделенной ёмкости двух ядер. За весь тест среднее CPU — 48.19%, память 113.21–135.39 МиБ. Ориентир CPU 60–80% не достигнут; искусственная дополнительная нагрузка не создавалась. Swap не использовался, но конфигурация допускает до 2 ГиБ swap.

Годовой расчёт №7 выдал 365 дней за **9.06 с**, запрос на его создание занял 24.74 мс. Параллельно отправлялись запросы прогнозов. Все **31 проверки API** прошли: доступ, неверные параметры, ошибки JSON/CSV, ограничения запросов и восстановление нормальной работы после ошибок.

Подтверждения: `tests/evidence/https_acceptance/`; скрипт повторения: `tests/acceptance.py`. Это тест с генератором на той же ВМ, а не независимое измерение задержки из сети посетителя. Точность модели этими нагрузочными тестами не измеряется.

## Масштабируемость и надёжность

Компоненты разделены: подготовка данных → прогноз → анализ сценариев → API и интерфейс. Чтение прогнозов можно развивать через несколько одинаковых экземпляров модели. В текущей версии годовые задачи хранятся в памяти одного экземпляра: для полноценного горизонтального масштабирования необходимы общая очередь и общее хранилище результатов. Работа нескольких реплик и восстановление после отказа не заявляются как проверенные.

Некорректные API-запросы возвращают контролируемые ошибки; 31 автоматическая проверка пройдена. Вход и передача данных защищены HTTPS. Приём исторических валидаций реализован пакетным CSV-пайплайном. Постоянного потокового HTTP-приёма событий пока нет; загрузка CSV для оценки не выдаётся за такой приём.

## Модель и качество

В папке `service/model/` — модель, установленная на сайте и использованная в тесте. Её соответствие подтверждено контрольной суммой из работающего контейнера. В исходном README команды заявлен WAPE-score 0.88512, но подтверждение результата платформы в архиве отсутствует; число 0.893744 относится к исследовательскому reference и не представляется как официальный результат.

Отдельно приложенная позднее модель находится в `additional_model/`: её файл отличается от установленного. Она сохранена как дополнительный артефакт без подмены модели сайта и без переноса на неё результатов теста. Подробности — `reports/05_MODEL.md`.

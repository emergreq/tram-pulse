# Годовой почасовой профиль

Ветка `ds1/forecast-submission`, отдельный исследовательский экспорт. Не
меняет `run.py`, его выбор конкурсной модели или отправленный CSV.

```bash
PYTHONPATH=. python -m ml.forecast.year \
  --labels /path/to/labels_day_train.csv /path/to/labels_day_test.csv \
  --cutoff 2025-10-31 --days 365 --out /path/to/year_forecast
```

Для календарного года: `--year 2026` вместо `--days 365`. При необходимости
использовать `--start YYYY-MM-DD --days N`, где `1 <= N <= 366` и первый день
позже отсечки. `--routes` по умолчанию содержит десять маршрутов из задания;
можно указать явный список через запятую. Любые входные метки после `cutoff`
завершают запуск ошибкой.

Выход: `yearly_forecast.csv` в формате
`route;date;hour;prediction`, `yearly_forecast_api.csv` с ISO-часом
`Europe/Moscow`, `model_version`, `as_of` и `quality_flag`, а также
`yearly_report.json` с хешами входов, кода и результатов. Из октябрьских
меток пример 01.11.2025–31.10.2026 даёт 87 600 строк, десять маршрутов ×
365 дней × 24 часа. Для маршрута 5 нет истории: значение 0 — технический
заполнитель с `unsupported_cold_start`, **не оценка пассажиропотока**.
Остальные строки помечены `long_horizon_unverified`.

Модель — медиана по маршруту, дню недели и часу, сглаженная на 20% к
маршрутно-часовой медиане. Погода, трафик, будущие ремонты и поздняя
геометрия не подставляются. Годовая точность неизвестна: доступны только
проверки горизонтов 4, 6 и 8 месяцев. Последние входные метки 2025 года
не снабжены временем появления; отчёт указывает на это ограничение.
Отчёт об источниках и длинном backtest хранится в исследовательской ветке
как `docs/research/EXPERIMENT_12_EXTERNAL_AND_YEAR.md`.
